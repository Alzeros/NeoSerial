# NeoSerial UI 重构设计（经典工程软件风格）

日期：2026-07-15
状态：已通过 brainstorming，待写实现计划

## 1. 背景与目标

当前 MVP 是单栏紧凑工具，已能收发与存盘。用户测试后提出 5 点调整，并另行撰写《UI 需求设计.md》，要求整体改为经典工程软件风格（参考 SSCOM / XCOM / SecureCRT）：信息密度高、一屏完成常用操作、控件紧凑、无圆角卡片、无复杂动画、优先效率而非美观。

本轮范围（已与用户确认）：**布局重构 + 顶部完整串口配置栏 + 右侧命令脚本侧边栏框架 + 底部快捷发送区 + 状态栏 + 用户提出的几个开关**。右侧侧边栏只搭框架（Tab + 命令列表，点一下即发送，UI 支持增删改），**不实现队列执行引擎**（顺序/延迟/重试/等待回复等留给后续阶段）。

## 2. 整体布局

三层 + 状态栏：

```
┌──────────────────────────────────────────────────┐
│ 顶部：串口连接配置栏（固定高度，紧凑）            │
├────────────────────────────┬─────────────────────┤
│                            │                     │
│  左：串口日志区（白底，70%）│ 右：命令脚本侧边栏  │
│                            │   （深色，30%）      │
│                            │                     │
├────────────────────────────┴─────────────────────┤
│ 底部：快捷发送区（输入框 + 行尾互斥按钮 + 发送）  │
├──────────────────────────────────────────────────┤
│ 状态栏：Connected / COM / Baud / TX / RX         │
└──────────────────────────────────────────────────┘
```

- 顶部、底部、状态栏固定高度；中间左右分栏自适应缩放。
- 左侧日志区约占 70%，右侧侧边栏约占 30%（可后续做成可拖拽分隔条，本轮固定比例）。
- 经典工程风格：控件间距小、无大量留白、无圆角卡片、无阴影、无动画。

## 3. 顶部——串口连接配置栏

只放连接相关配置，全部横向排列，标签在控件左侧，控件高度一致，整体紧凑：

```
COM [COM5▼]  Baud [115200▼]  数据位 [8▼]  校验 [None▼]  停止位 [1▼]  流控 [None▼]  [Connect] [Disconnect]   状态文字
```

- COM：下拉，值来自 `serialport::available_ports()`，2s 刷新（已有）。
- Baud：下拉，预设档位 9600/19200/38400/57600/115200/230400/460800/921600。
- **数据位 / 校验位 / 停止位 / 流控**：本轮新增暴露。`Settings.SerialDefaults` 已有这些枚举（DataBits/Parity/StopBits/FlowControl），此前 UI 未接、固定用默认值。本轮接上：下拉选择 + 持久化。
- Connect / Disconnect 按钮：Connect 用主色（蓝），Disconnect 用红。互斥启用（连接时只 Disconnect 可点）。
- 末尾状态文字（已连接/未连接/错误）。

## 4. 中间左侧——串口日志区

最重要区域，占最大空间。**白底黑字**，大型文本区。

- 等宽字体 Consolas。
- 自动滚动（开关在底部或顶部工具栏，本轮保留现有手动开关）。
- 每行格式：`[时间戳] [方向tag] 内容`（时间戳与方向 tag 各自受开关控制，见 §7）。
- 收发颜色区分：白底下可辨的颜色——TX 用深绿、RX 用黑/深灰、ERROR 用红。
- 支持清空（已有）、可复制（文本原生支持）。搜索/过滤留后续阶段。
- 不做卡片、阴影、圆角。

## 5. 中间右侧——命令脚本侧边栏（框架）

工具最大特色。本轮搭框架，不做队列执行引擎。

### 5.1 数据模型（可扩展，按《UI 需求设计.md》§九设计）

```
CommandGroup          // 一个 Tab 对应一个 Group
└── CommandItem[]     // 每行一个命令
```

**CommandItem 本轮字段**（精简，未来可扩展超时/重试/等待回复/变量替换/脚本）：

| 字段 | 说明 |
|---|---|
| label | 显示名 / 按钮 |
| content | 发送内容 |
| mode | 0=ASCII 1=HEX |
| ending | 行尾 0=Cr 1=Lf 2=Crlf 3=None |
| enabled | 是否启用（本轮框架占位，引擎未实现时无实际效果，但字段保留以对齐数据模型） |

> 说明：本轮 CommandItem 不含「执行顺序/发送延迟」等执行引擎字段——引擎未实现，写了也是死字段（YAGNI）。仅保留 `enabled` 作为框架占位，因为它是 UI 上「勾选是否启用」的直观字段，且为后续引擎预留语义。
>
> **交互确认**：本轮侧边栏只支持「点一下某条命令 → 立即发送这一条」，**不做顺序执行**（点 Run 按顺序自动发一串）。顺序执行引擎（含执行顺序/发送延迟/重试/超时/等待回复等字段）留后续阶段，届时再扩 CommandItem 字段。

### 5.2 UI 形态

- 顶部 Tab 栏：本轮单 Tab「默认」，但 Tab 控件本身按多 Tab 设计（数据模型 `Vec<CommandGroup>`），后续可加 Tab。
- Tab 下方命令列表：每个 CommandItem 一行（按钮或列表项），点一下即发送该命令。
- 列表下方「+」按钮：新增命令。
- 每条命令可编辑/删除（点命令进入编辑，或行内编辑按钮）。
- 命令从 `settings.json` 加载（复用现有 `QuickCommand` 结构，扩展为 `CommandGroup` 包裹）。

### 5.3 与底部发送区的区别

- 右侧侧边栏：固定脚本，存配置，反复使用。
- 底部发送区：临时命令，发完即弃。
- 两者不混合。

## 6. 底部——快捷发送区 + 状态栏

### 6.1 快捷发送区

```
[输入框 AT+CFUN=1,1 ............]  [CR][LF][CRLF][无]  [HEX]  [发送]
```

- 输入框：回车发送，↑↓ 调历史（已有）。
- **行尾选择改为紧凑互斥按钮组**：CR / LF / CRLF / 无，四个小按钮，点中即选中（高亮），不再用大 ComboBox。这是用户第 4 点反馈。
- HEX 开关：切换本条发送是 ASCII 还是 HEX。
- 发送按钮：主色。

### 6.2 状态栏（新增）

底部最底一行，实时刷新：

```
● Connected   COM5   115200   TX: 10234 B   RX: 83912 B
```

- 连接状态点（绿=连接/红=断开）+ COM + Baud。
- TX/RX 累计字节数：读线程上报，UI Timer 拉取刷新。

## 7. 显示开关（用户第 2、3 点）

放顶部工具栏（与 ASCII/HEX、暂停、清屏、存盘、自动滚动 同区）。本轮顶部拆为两行或加宽以容纳：连接配置一行 + 显示开关一行。具体：

- **时间戳开关**：开 → 屏幕每行 + 日志文件每行都带时间戳 `HH:MM:SS.mmm`；关 → 都不带。
- **记录发送开关**：开 → 发送的指令进屏幕 + 日志，带 `[发送]` tag；关 → 发送不记录（只发不显）。接收始终带 `[接收]` tag、始终记录。
- 方向 tag：中文 `[发送]` / `[接收]`，同时用于屏幕显示和存盘文件。
- ASCII/HEX 切换、暂停、清屏、存盘、自动滚动：保留。

> 行格式示例（时间戳开 + 记录发开）：`08:00:01.123 [发送] AT` / `08:00:01.456 [接收] OK`
> 行格式示例（时间戳关 + 记录发关）：`[接收] OK`（发送不出现）

## 8. 存盘改动（用户第 1、2、3 点 + 推翻 C1）

### 8.1 格式

- **改为格式化文本日志**（WYSIWYG），默认后缀 `.log`（保留 `.bin` 过滤器可选）。
- 存盘文件 = 屏幕看到的格式：每行 `[可选时间戳] [方向tag] 内容\n`。

### 8.2 取舍（已与用户确认）

- **推翻之前 C1 的「原始字节捕获」设计**：存盘不再由读线程把 `buf[..n]` 直接甩给 FileLogger。
- 改为：存盘记录的是「成行的 LogLine」（带 tag/时间戳/内容）。
- **半行数据（未收到换行符的字节）不会立即落盘**，等行结束（收到换行符）才写。
- 适用于 AT/调试日志场景；非文本二进制协议捕获留给后续阶段另想方案（如独立的原始字节捕获开关）。

### 8.3 数据流

- 读线程切出完整行 → 生成 LogLine → 经 event channel 送 UI（已有路径）。
- **存盘开关开时**，UI（或读线程）把已格式化的行文本（含 tag/时间戳，按开关状态）发给 FileLogger。
- FileLogger 改为写文本行（`String`/`Vec<u8>` UTF-8），而非原始字节 chunk。
- 「记录发送」开关关时，TX 行不进存盘。
- 时间戳开关关时，存盘行也不带时间戳。

### 8.4 存盘 UI（保留上一版改进）

- 默认关，点「开始存盘」弹原生「另存为」选位置后才开。
- 默认文件名 `neoserial_YYYYMMDD_HHMMSS.log`。
- 存盘中显示「📂 所在文件夹」+「⏹ 停止存盘」。
- 存盘失败通知 UI + 红字（已有 error_tx 机制）。

## 9. 配置持久化

`settings.json` 扩展：

- `SerialDefaults`：数据位/校验位/停止位/流控已有，本轮 UI 接上后可改并持久化。
- 新增显示开关：`show_timestamp: bool`、`log_send: bool`（记录发送）。
- `quick_commands` 扩展为 `command_groups: Vec<CommandGroup>`（包裹 CommandItem 列表）。向后兼容：若无 `command_groups` 字段，把旧 `quick_commands` 迁移为单个「默认」Group。
- 窗口尺寸/位置/last_port/display_mode/line_ending/auto_scroll：保留。

## 10. 架构影响

- **connection/ 模块仍不依赖 slint**（不变）。
- 读线程：切行逻辑不变；新增 TX/RX 字节计数上报（状态栏用）。存盘改为走格式化行文本——决定存盘点在 UI 侧还是读线程侧（实现时定，倾向 UI 侧：读线程只产 LogLine，UI 按开关格式化后送 FileLogger，逻辑集中、开关即时生效）。
- FileLogger：从写 `Vec<u8>` 原始 chunk 改为写格式化行文本。
- LogLine：已有 raw/ascii/hex/is_error/dir/ts，足够支撑格式化。新增「是否进入存盘/显示」由 UI 开关在渲染与存盘时过滤，不改 LogLine 结构。
- 新增侧边栏组件、状态栏组件、行尾互斥按钮组组件。

## 11. 不在本轮范围（YAGNI / 后续阶段）

- 命令队列执行引擎（顺序/延迟/重试/超时/等待回复/条件执行/循环/变量替换/脚本）。
- 多 Tab 命令组的 UI 管理（本轮单 Tab，模型预留）。
- 可拖拽分隔条（本轮固定 70/30）。
- 日志搜索/过滤/正则/高亮/收藏。
- 多串口标签页、多设备管理。
- HEX 十六进制网格双面板。
- 原始字节捕获（被格式化存盘取代，未来可作独立开关）。
- 深色/浅色主题切换（本轮日志区固定白底，其余深色）。

## 12. 测试策略

- 纯逻辑模块 TDD：时间戳格式化（已有）、行格式化函数（新增：根据开关生成 `[ts] [tag] content` 字符串）、CommandGroup/CommandItem 序列化往返、settings 迁移（旧 quick_commands → command_groups）。
- FileLogger 改为文本行后，测试写入的行格式正确、时间戳/tag 受开关控制。
- UI 布局/交互靠手动验证。
- 本轮测试聚焦变更点，不全量跑（用户要求：功能调试阶段只测涉及变更的点）。
